# PS ComfyUI 桥接（自动版）

一个 Photoshop UXP 面板插件：把 PS 里正在修的图一键送到 ComfyUI 处理，处理完**自动置入回原来的文档**，不用手动导出、切换软件、再拖回来。

```
PS 打开图 → 点「发送」→ 插件导出 JPG 并上传 ComfyUI
        → ComfyUI 按工作流处理 → 插件轮询到结果
        → 自动置入回原来那张 PS 文档 ✅
```

## 功能

- **一键发送**：导出当前文档为 JPG → 上传到 ComfyUI → 自动替换工作流里的 `LoadImage` 节点 → 提交队列
- **自动回图**：后台轮询结果（约 3 秒一次，最长约 15 分钟），完成后自动置入**原文档**（按文档 ID 找回，中间切到别的图也不会放错）；置入失败时自动改为打开为新文档
- **多张排队**：可以连续对多张图点发送，各自处理完各自回原文档，互不覆盖
- **手动补拉**：超时或面板重开后，可用第二个按钮补拉未完成的任务
- ComfyUI 地址和工作流文件名都可以在面板里改，本地和云端（如 Cloud Studio）都能用

## 开始前先备齐这 3 样

| 需要的东西 | 说明 |
|---|---|
| Photoshop 24.6+ | 低于这个版本装不了 UXP 插件 |
| 能打开的 ComfyUI | 本地装好的，或云端（如 Cloud Studio）给的地址。先在浏览器里打开一次，能看到 ComfyUI 界面才算通 |
| UXP Developer Tool | Adobe 官方免费工具，用来把本插件加载进 PS：[下载地址](https://developer.adobe.com/photoshop/uxp/2022/guides/devtool/) |

> ⚠️ 本插件是**用 Developer Tool 加载**的方式，不是双击安装的 `.ccx` 包，第一次装要多走两步，下面一步步来。

## 第一步：下载插件

1. 在本仓库页面点绿色的 **Code** 按钮 → **Download ZIP**
2. 解压 ZIP
3. 打开解压出来的文件夹确认一眼：`manifest.json`、`index.js`、`index.html` 就在这一层

> ✅ 成功标志：你能在这个文件夹里直接看到 `manifest.json`。
> 如果要点开两层文件夹才看到，说明多套了一层，第 2 步选文件时选到有 `manifest.json` 的那一层就行。

（会用 git 的也可以直接 `git clone` 本仓库，效果一样。）

## 第二步：把插件加载进 PS

1. 打开 **UXP Developer Tool**
2. 点 **Add Plugin**，选择第一步那个文件夹里的 `manifest.json`
3. 列表里会出现「PS ComfyUI 桥接（自动版）」，点它右侧的 **Load**（有的版本是点 `···` 菜单里的 Load）
4. 打开 Photoshop，点菜单 **增效工具 / Plugins** → **ComfyUI 桥接（自动版）**

> ✅ 成功标志：PS 里出现插件面板，能看到「ComfyUI 地址」「workflow_api.json」两个输入框和两个按钮。
> PS 没开着的时候 Load 会失败，先开 PS 再 Load。

## 第三步：先确认 ComfyUI 是通的

1. 启动你的 ComfyUI（本地的先启动；云端的确认服务在运行）
2. 把它的地址填到浏览器里打开一次 — 本地默认就是 `http://127.0.0.1:8188`
3. 浏览器能打开 ComfyUI 界面后，把**同一个地址**填进插件面板的「ComfyUI 地址」（末尾带不带 `/` 都行）

> ✅ 成功标志：浏览器里能看到 ComfyUI 的节点界面。这一步不通，后面一定失败，先别急着点发送。

## 第四步：在 PS 里跑第一张图

1. 在 PS 里打开一张要处理的图
2. 确认面板里的「工作流文件名」写的是插件目录里真实存在的文件（第一次先用默认的 `workflow_api.json`，它的依赖见下面「示例工作流」一节；依赖没配齐的话，先按第五步换成你自己已经跑通的工作流再回来点发送）
3. 点 **「1. 导出当前图并发送到 ComfyUI 处理」**
4. 看面板下方的状态日志：会依次显示导出完成 → 上传成功 → 任务已提交 → 正在处理
5. 什么都不用做，等处理完成，结果图会**自动置入回这张图**成为新图层

> ✅ 成功标志：日志显示「已自动置入原文档」，PS 里多出一个处理后的图层。
> 中途可以切去处理别的图，回来时它会自己找到原文档，不会放错。

## 第五步：添加 / 换你自己的工作流（重点看这里）

记住三条规则，后面就不容易踩坑：

1. **文件必须放在插件根目录**（和 `index.js` 同一层），`examples/` 里的文件不能直接用，要先复制出来
2. **面板里只填文件名**，比如 `my-workflow.json`，不要填完整路径
3. **必须是 API 格式**的工作流 json（怎么导出见 B），普通保存的工作流文件不能用

### A. 用仓库自带的示例工作流

1. 把 `examples/ps-ai.json`（或 `pc-ai-cloudstudio.json`）复制一份到插件根目录
2. 面板第二个输入框把 `workflow_api.json` 改成 `ps-ai.json`
3. 回到第四步点发送

> 注意：示例依赖特定的模型和自定义节点（清单在下面），你 ComfyUI 里没有的话会报红，那是示例的依赖问题，不是插件坏了。

### B. 用你自己的 ComfyUI 工作流

1. 在 ComfyUI 里先把这个工作流**自己手动跑通一次**（能正常出图再往下走）
2. 确认工作流里有这两个节点，缺一个插件都用不了：
   - **LoadImage**（加载图像）— 插件会自动把它的图片换成 PS 传来的图，它原来选的是哪张图不用管
   - **SaveImage**（保存图像）— 插件从这里的输出取回结果图
3. 导出 API 格式：点 ComfyUI 右上角设置（齿轮）→ 勾选 **Enable Dev Mode（开发者模式）** → 界面会出现 **Save (API Format)** 按钮，点它导出（新版界面里也可能在菜单的「导出 (API)」里，认准 **API** 字样）
4. 把导出的 json 文件放到插件根目录，起个简单文件名，比如 `my-workflow.json`
5. 面板第二个输入框填 `my-workflow.json`，回到第四步点发送

> ✅ 成功标志：日志显示「任务已提交」，ComfyUI 的队列里能看到这个新任务。
> 换文件、改文件后**不用重装、不用重新 Load 插件**，每次点发送时插件都会重新读取一遍该文件。

### 怎么分辨导出的到底是不是 API 格式？

用记事本打开 json 看一眼：

- ✅ API 格式：内容是一个个节点编号，每个节点里有 `"class_type"`（如 `"class_type": "LoadImage"`）
- ❌ 普通格式：内容里有 `"nodes"`、`"links"` 这些词 — 这是画布存档，插件读不了，回去按 B 第 3 步重新导出

## 示例工作流（examples/）

仓库附带了 3 份示例，都是同一套 Flux 分块高清修复 / 产品精修流程，仅供参考，本插件本身不绑定任何工作流：

| 文件 | 说明 |
|---|---|
| `workflow_api.json`（根目录） | 默认示例，denoise 0.2 |
| `examples/pc-ai-cloudstudio.json` | 云端版，denoise 0.3 |
| `examples/ps-ai.json` | 本地版变体，denoise 0.3 |

直接跑这些示例需要你自己的 ComfyUI 里有以下模型和自定义节点，缺任何一个 ComfyUI 都会报红，这属于示例的依赖、不是插件的依赖：

- **模型**（示例里只是引用文件名，模型文件不在本仓库内）：
  - UNET：`绘梦光影魔术师 F.1 -全能写实-商业电商产品广告摄影_光影全能魔术师_V1.safetensors`
  - VAE：`ae.sft` / `ae.safetensors`
  - CLIP：`t5xxl_fp8_e4m3fn.safetensors` + `clip_l.safetensors`
  - LoRA：`Flux Dev模型4步出图lora_Flux Dev 4-step.safetensors`
  - 放大模型：`4x-AnimeSharp.pth`
- **自定义节点**（在 ComfyUI Manager 里按节点名搜索安装）：`TTP_Image_Tile_Batch` / `TTP_Tile_image_size` / `TTP_Image_Assy`、`LayerUtility: ImageScaleByAspectRatio V2`、`CR Simple Image Compare`、`easy imageBatchToImageList` 等
- 示例里的提示词是针对某一个化妆品产品的，换图时请改成你自己的描述

**建议**：第一次用先换成你自己已经能跑通的工作流（第五步 B），确认插件链路没问题，再折腾示例。

## 常见问题

| 现象 | 原因和解决办法 |
|---|---|
| 面板里点发送，提示找不到 workflow 文件 | 文件没放进插件根目录，或面板里文件名写错（包括后缀）。对照第五步三条规则检查 |
| 上传失败 / 提交失败，连不上 | ComfyUI 没启动，或面板里地址不对。回到第三步，先在浏览器里打开那个地址验证 |
| ComfyUI 里节点报红、任务报错 | 工作流缺模型或自定义节点。先在 ComfyUI 里手动跑一遍这个工作流，缺什么补什么 |
| 日志说找不到 LoadImage 节点 | 工作流里没有 LoadImage，或导出的不是 API 格式。按第五步 B 检查 |
| 等了很久没回图 | 轮询最长约 15 分钟，云端排队久了会超时。任务可能还在 ComfyUI 里跑，跑完后点面板第 2 个按钮「手动补拉结果」即可 |
| 结果图没有置入原文档，而是打开成了新文档 | 原文档处理期间被关掉，或置入失败时插件自动改成新文档打开，结果不会丢 |
| Developer Tool 里 Load 失败 | 先打开 Photoshop 再 Load；PS 版本低于 24.6 也会失败 |

## 已知限制

- 导出的是当前文档的合并 JPG（质量 12），不是分层 PSD
- 结果图取工作流第一个带图片输出的节点
- 轮询最长约 15 分钟，云端排长队时可能超时，超时后用「手动补拉」按钮重试即可
